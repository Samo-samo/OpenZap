# Contributing

Thank you for your interest in contributing to OpenZap.

The project is still in its early stages, so architectural consistency is more important than rapid feature development.

---

# Before Contributing

Please read the following documents before making changes:

* [PRD.md](https://github.com/Samo-samo/OpenZap/blob/main/PRD.md)
* [docs/ARCHITECTURE.md](https://github.com/Samo-samo/OpenZap/blob/main/docs/ARCHITECTURE.md)
* [docs/ROADMAP.md](https://github.com/Samo-samo/OpenZap/blob/main/docs/ROADMAP.md)

---

# Development Principles

* Keep implementations simple.
* Follow the documented architecture.
* Avoid unrelated refactoring.
* Discuss major architectural changes before implementing them.
* Prefer maintainability over clever solutions.

---

# Commits

Use Conventional Commits whenever possible.

Examples:

* feat:
* fix:
* docs:
* refactor:
* test:
* chore:

---

# Pull Requests

A pull request should:

* solve a single problem;
* remain focused;
* include documentation updates when required;
* avoid unrelated changes.

---

# Issues

When reporting a bug or requesting a feature, include enough information to reproduce or understand the problem.

Clear reports help everyone.

---

# Code Style

* Write readable code.
* Keep functions focused.
* Avoid unnecessary abstractions.
* Follow the existing project structure.

---

Thank you for helping improve OpenZap.
